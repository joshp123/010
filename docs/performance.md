During dragging, pinching, rotation and wheel bursts, the camera and rendering continue using the currently selected source tiles. Tile selection, bridge reconciliation, surface indexing and road reprojection resume after release and 120 ms without input. A long gesture into unloaded territory can therefore show cartographic fallback until it ends. Full detail then loads normally; deferred selection reports pending readiness, and full-detail export bypasses this deferral. Already-running source decoding can still consume CPU during input.

Prepared model delivery uses gzip sidecars generated by `scripts/compress-model-assets.mjs` after `vinext build`. Raw GLBs remain unchanged in `public/` and in build output; the extra `.glb.gz` files exist only in `dist/client/data/`. One exported directory set is shared by the builder and loader. The terminal reconstruction freed enough publication space to also compress green terrain and industrial ground, previously excluded by the 256 MiB archive limit. The candidate adds 31,695,876 sidecar bytes for those 638 files, compared with 42,033,768 raw bytes; this is a whole-layer estimate, not one view’s transfer or a loading-time claim. The loader's small `fetchData` plugin requests these sidecars only for same-origin `/data/*.glb` URLs within that shared selection and uses native `DecompressionStream` before the existing Three.js parser. A missing sidecar falls back to the original GLB for source previews; browsers without native decompression use the default raw loader. External native Rotterdam tiles, cancellation signals, geometry and model URLs in source manifests are unchanged. No compression dependency or proxy API is added. Sidecars increase the deployment archive size; they reduce browser transfer, not geometry decoding cost.

A standard geometry-compression experiment used [meshoptimizer v1.0](https://github.com/zeux/meshoptimizer/tree/73583c335e541c139821d0de2bf5f12960a04941/js), retaining the original B3DM metadata. Lossless compression without quantization grew three samples by 25–42% versus gzip. Official mesh reordering plus bounded position/normal packing reduced centre and west-port ground by 26.6–28.7%, and representative bridges/buildings by 44.1–44.4%. Actual vendored-loader checks measured at most 8.68 mm position error and 0.233° normal error; oriented triangle sets, feature IDs and material assignments were preserved. However, re-running source ground classification on rounded coordinates changed three skirt-triangle decisions. Such a pipeline must classify original measurements before packing and separately verify bridge reconciliation and rendered appearance. It is not a drop-in lossless replacement. These sample savings did not justify another hosting pipeline by themselves, so no runtime compression, geometry or hosting change was made. Reproducible research, pinned tools, original-source hashes and results remain on the SSD in `work/compression/`; `README.md`, `QUANTIZED.md` and `REORDERED.md` distinguish the three experiments.
