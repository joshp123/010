# Pilot facade correspondence limits

BAG0599100000671699, Schiedamseweg26; unchanged current triangles624/625. This investigation changes **no** MFLUX source, mask, generated image, runtime asset or architecture.

`python scripts/inspect-pilot-correspondence.py` projects the older municipal edition's matching facade triangles into the exact current pilot camera. It composes original node matrices, glTF up-axis and RTC through ECEF; the two old triangles lie within1cm of the measured current facade plane. The current source/mapping hashes, original triangle identities, plane distances and matrix are recorded in `comparison.json`. Both editions are preserved. Inspect `same-plane-comparison.jpg`.

The current source clearly supports four principal upper-storey openings (two on each of two storeys), pale frames, horizontal transoms and masonry bands, plus contrasting brick infill. Their observed frame edges can constrain an image model **in the existing photographed coordinate system**. They are not independently calibrated real-world corner coordinates. Frames and bands show residual shear after plane unwrapping. The source geometry itself is effectively vertical; this warp is carried in the texture observation. The native current atlas is1024²: the entire5.08×13.11m facade occupies an axis-aligned atlas bound of only about154×239pixels. The512×1024 panel is an enlarged view, not new photographic evidence. Small sill/frame corners cannot be treated as precise surveyed points.

The older edition supplies a second published texture, but the actual same-plane image is too smeared to identify four matching opening corners reliably. It cannot justify a corrective homography, nor certify current opening proportions. The published editions do not establish independent camera calibration/date or provide original oblique camera matrices. Opposing CPU model views of the current atlas are **not** independent photographs. The glazing annotation inventory was fitted to that same current source, so it is a useful source-support annotation but not independent rectification evidence.

No geometrically corrected panel was produced: enforcing rectangular windows, parallel bands or equal spacings would add an architectural prior not validated by independent observations here. Likewise, a generated image with cleaner but shifted/proportionally altered openings is not evidence for a correction. Storefront lettering, recessed depth, frame thickness and partly occluded details remain uncertain. Keep generated output out of the runtime until its layout is reviewed against the source.

A useful next input is a dated, permitted frontal or oblique street photograph of this exact facade with at least four clearly corresponding points, preferably additional independent edge/corner checks. A measured facade elevation or municipal original oblique photo plus camera calibration would be stronger. Once supported, retain observations and uncertainty, estimate and validate the transform against unused correspondences, and keep inverse mapping to original UVs. This repository currently lacks that independent evidence for this exact pilot. The manager's same-source second style trial must stay unchanged to isolate its style effect.
